# Деплой сервиса agent-system

Сервис это обычное Python-приложение на FastAPI, которое слушает порт 8000 и отвечает бэкенду по HTTP. Разворачивать его удобнее всего через Docker, тогда на сервере не нужен ни Python, ни виртуальное окружение.

Сначала на сервере должен стоять Docker. Рядом кладётся папка agent-system и файл с ключами. Файл с ключами это .env, его в репозиторий не коммитят, он готовится прямо на сервере по образцу .env.example. Внутри лежат ключи всех моделей и общий секрет AGENT_SYSTEM_API_KEY, которым бэкенд авторизуется у сервиса. Модель без ключа просто не используется.

Образ собирается один раз командой docker build -t mindarena-agents ./agent-system из корня проекта. Запуск командой docker run -d --restart unless-stopped -p 8000:8000 --env-file agent-system/.env --name mindarena-agents mindarena-agents. Здесь -d запускает контейнер в фоне, --restart поднимает его снова после перезагрузки сервера, --env-file передаёт ключи внутрь, не зашивая их в образ.

После запуска сервис проверяется обращением на его адрес с путём /health. Там должен вернуться статус ok и список поднятых моделей. Если модели там нет, значит у неё нет валидного ключа, и в дебатах она не участвует. Полное описание API и интерактивная документация доступны на самом сервисе по путям /docs и /redoc, а способ вызова для бэкенда описан в файле API.md.

Обновление версии это остановка старого контейнера командой docker rm -f mindarena-agents, пересборка образа и повторный запуск. Внутри сервис ничего не хранит, весь стейт держит бэкенд, поэтому терять при перезапуске нечего.

Порт 8000 наружу в интернет открывать не нужно. Бэкенд и сервис должны находиться в одной приватной сети или на одной машине, а снаружи доступен только бэкенд. Ключи после первой интеграции стоит заменить на новые, потому что первичные передавались в открытом виде.

Если Docker по каким-то причинам не подходит, тот же сервис запускается напрямую через Python 3.11. Нужно создать виртуальное окружение, установить зависимости командой pip install -r requirements.txt, положить .env и запустить командой uvicorn app.main:app --host 0.0.0.0 --port 8000. Для постоянной работы это оборачивают в systemd-юнит или процесс-менеджер вроде supervisor, чтобы сервис поднимался автоматически.
